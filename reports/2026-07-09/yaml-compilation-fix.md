# Technical Report: Resolving `tree-sitter-yaml` Compilation and Path Inclusion Error
**Date:** July 9, 2026  
**Subject:** Fixing the YAML grammar header lookup issue using source-specific properties to maintain build safety and prevent global macro collisions.

---

## 1. Introduction and Context

During the expansion of the DECODE local code intelligence engine, support for the **YAML** programming/config language was added by integrating the `ikatyang/tree-sitter-yaml` repository (at tag `v0.5.0`) into our C++ CMake project. 

However, during compilation, the build failed with the following compilation error:
```
/deps/tree-sitter-yaml-src/src/parser.c:1:10: fatal error: tree_sitter/parser.h: No such file or directory
    1 | #include <tree_sitter/parser.h>
```

To resolve a previous issue regarding **redefinition conflicts (e.g. `REDUCE`, `SHIFT` macros)** across different grammar source files, all language-specific source folders (such as `${tree-sitter-python_SOURCE_DIR}/src`) had been intentionally removed from the global CMake `target_include_directories` list. Only the core tree-sitter header directories were left in the global search path.

This report details why this change caused `tree-sitter-yaml` to fail, why other language grammars did not fail, and how we fixed it cleanly without reintroducing the global namespace pollution.

---

## 2. Technical Analysis & Root Cause

### A. Preprocessor Include Syntax: Angle Brackets (`<>`) vs. Double Quotes (`""`)

We performed a deep inspection of how each grammar includes `parser.h`. We ran a recursive grep across all downloaded tree-sitter grammars:
```bash
grep -rn "tree_sitter/parser.h" _deps/*-src/src/parser.c
```

The output revealed a critical syntactic difference in `parser.c` files generated by different versions of the `tree-sitter` CLI:

- **Python, JavaScript, C++, Go, Rust, Bash, JSON:**
  ```c
  #include "tree_sitter/parser.h"
  ```
- **YAML (`tree-sitter-yaml`):**
  ```c
  #include <tree_sitter/parser.h>
  ```

Under C and C++ preprocessor standards:
1. **Double Quotes (`#include "file"`)**: The compiler searches for the header relative to the directory of the source file containing the include statement. Since every grammar repository vendors a local copy of `tree_sitter/parser.h` inside its own `src/` directory (e.g. `src/tree_sitter/parser.h`), files like `tree-sitter-python`'s `parser.c` were able to find `parser.h` relatively, even without any global include paths.
2. **Angle Brackets (`#include <file>`)**: The compiler skips searching the source file's directory and searches **only** the list of directories explicitly added to the include search path (usually via `-I` compiler flags). Because we removed all language-specific folders from `target_include_directories` to avoid macro collisions, the compiler could not locate `<tree_sitter/parser.h>` for YAML.

### B. The Danger of Re-introducing Global Include Paths

If we simply added `${tree-sitter-yaml_SOURCE_DIR}/src` to the global `target_include_directories` of the `codelens_core` target:
- Any other source file in the project could implicitly lookup files in `tree-sitter-yaml`'s source folders.
- If multiple language folders were added globally, it would lead to header name collisions and macro redefinition conflicts (such as `REDUCE` redefinition warnings or compilation failure due to conflicting parser states).

We needed a solution that added the include path **only** when compiling `tree-sitter-yaml`'s files.

---

## 3. The Solution: Source-Specific Include Paths

We leveraged a feature in CMake: **source-file-specific properties**. 

Instead of configuring include paths at the target level (which affects all files in the target), CMake allows assigning properties directly to individual source files. Using `set_source_files_properties`, we can assign a specific `INCLUDE_DIRECTORIES` property to only the YAML source files:

```cmake
set_source_files_properties(
    ${tree-sitter-yaml_SOURCE_DIR}/src/parser.c
    ${tree-sitter-yaml_SOURCE_DIR}/src/scanner.cc
    PROPERTIES INCLUDE_DIRECTORIES "${tree-sitter-yaml_SOURCE_DIR}/src"
)
```

### Why this is the optimal C++ build engineering solution:
1. **Perfect Isolation**: Only `parser.c` and `scanner.cc` of `tree-sitter-yaml` receive the `-I .../tree-sitter-yaml-src/src` include search flag.
2. **Zero Pollution**: No other source files (such as bindings, other parser files, or helper C++ utilities) have this path added, preserving the clean compile environment and completely preventing macro collisions.
3. **No Code Modification**: We did not need to modify the vendored tree-sitter dependency files (which would be overridden on a clean dependency fetch or cause git diff pollution).
